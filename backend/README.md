# CTF Insight AI — Backend

FastAPI backend. Clean architecture: `api/` (routers) → `services/` (business logic) → `repositories/` (data access) → `models/` (SQLAlchemy ORM). See `/docs` at repo root for the full architecture and API contract.

## Prerequisites
- Docker + Docker Compose
- Python 3.12 (only needed if running outside Docker)

## Quick start (Docker — recommended)

```bash
cp .env.example .env
# fill in at least JWT_SECRET_KEY (any random 32+ char string for local dev)

cd ..   # repo root
docker compose -f infra/docker-compose.dev.yml up --build
```

This starts Postgres (with pgvector), Redis, and the API. Migrations run automatically on container start. Once up:

- API: http://localhost:8000
- Swagger docs: http://localhost:8000/docs
- Health check: http://localhost:8000/api/v1/health
- Readiness (DB + Redis check): http://localhost:8000/api/v1/health/ready

## Running locally without Docker

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# point DATABASE_URL / DATABASE_URL_SYNC at a local Postgres, REDIS_URL at a local Redis

alembic upgrade head
uvicorn app.main:app --reload
```

## Migrations

```bash
# Create a new migration after changing models/
alembic revision --autogenerate -m "describe the change"

# Apply migrations
alembic upgrade head

# Roll back one revision
alembic downgrade -1
```

The initial migration (`0001_initial_schema.py`) was authored by hand against the Milestone 1 schema spec rather than autogenerated, since it's the very first migration with no prior DB to diff against. Every migration after it should be generated with `--autogenerate` and reviewed before committing — never hand-edited blind.

## Tests

```bash
pytest
# with coverage:
pytest --cov=app --cov-report=term-missing
```

`tests/integration/test_health.py` exercises the real app against real DB/Redis connections — run `docker compose up` first or the readiness test will (correctly) report a degraded status.

## Project layout

```
app/
├── main.py            # FastAPI app factory
├── core/               # config, logging, security, exceptions, rate limiting
├── db/                 # engine/session setup + Alembic migrations
├── models/             # SQLAlchemy ORM models (one file per table)
├── schemas/             # Pydantic request/response models (Milestone 3+)
├── repositories/        # data access layer (Milestone 3+)
├── services/            # business logic (Milestone 3+)
├── api/v1/              # route handlers
├── ai/                   # LLM provider abstraction, RAG, prompts (Milestone 7+)
├── workers/              # async job queue consumers (Milestone 7+)
└── storage/              # Supabase Storage adapter (Milestone 5+)
```

## What exists as of Milestone 2
- App factory with CORS, rate-limit scaffolding, structured logging, consistent error envelope
- Full ORM model layer for all 20 tables (see `docs/ER_DIAGRAM.md`)

- No business logic in `services/`/`repositories/` yet — those directories are empty pending Milestone 3+
- No AI pipeline wiring yet (Milestone 7+) — `ai/` directories are empty
